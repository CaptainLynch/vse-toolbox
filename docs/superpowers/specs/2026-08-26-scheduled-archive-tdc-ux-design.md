# 定时归档与 TDC 查询体验设计

## 目标

修复定时归档工作台的任务生命周期、凭据配置、目录选择、筛选条件和重试策略体验，并让 TDC 数模报表在“响应速度”和“与官方 Excel 完全一致”之间提供明确可选的模式。

## 现状与约束

- 后端 API 使用 camelCase 的归档任务字段；外部 TDC 交付物查询使用 snake_case 字段。两者必须通过集中式字段定义转换，不能让页面各自维护隐式映射。
- 归档任务只能写入 `ArchiveStore` 的批准根目录。任务的 `outputSubdir` 是批准根目录下的相对子目录，不允许绝对路径、网络路径、反斜杠或路径穿越。
- 生产定时任务通过 Windows DPAPI 保护库读取统一域账号，凭据引用的生产值固定为 `domain`（兼容 `unified-domain`）；用户名和密码不得进入任务配置、API 返回或日志。
- 内置归档任务只能禁用；自定义任务可以软归档并从活动列表移除。
- TDC 官方导出接口生成完整 XLSX，速度明显慢于分页 list 接口；精确模式必须接受该服务端耗时并显示进度，不能静默降级为 list 数据。
- 当前工作区存在大量前序未提交改动，实施只能增量修改相关文件，不得 reset、checkout 或删除用户文件。

## 设计决定

### 定时任务

1. 前端使用 API 返回的 `builtin` 字段。
2. 内置任务显示“内置任务，仅可停用”，不显示归档取消按钮；自定义任务显示软归档按钮。
3. 凭据配置改为明确的统一域账号引用选项，并在保存/启用前验证保护库可用性；保留清除引用操作。
4. 每个任务根据模板渲染可视化筛选表单，JSON 只作为高级编辑入口。表单保存时转换为当前后端归档字段，保持现有校验边界。
5. 输出目录分为“归档根目录”和“根目录下子目录”。本地 EXE 提供 Windows 原生目录选择器；选择结果必须经过本机、批准根目录和重解析点校验。网页安全目录浏览器作为回退。
6. 重试策略显示“最多尝试 N 次（失败后重试 N-1 次）”。任务级策略可配置；若本轮无法改变数据库公共契约，则至少移除误导性的无效全局设置并保持固定策略语义一致。

### TDC 查询

1. 快速查询默认调用分页 list 接口，并在结果中标注 `data_source=list_endpoint`。
2. 官方精确预览调用 XLSX export，读取官方 47 列表头和行数据，并标注 `data_source=official_export`。
3. 精确导出的临时文件按规范化筛选条件和当前认证会话做短时缓存，缓存不保存密码、Cookie 或 Authorization；TTL 默认 3 分钟，大小和条数受现有上限约束。
4. 分页、下载和同一筛选条件的精确预览优先复用缓存工作簿；缓存失效后重新导出。
5. TDC 定时归档不再为同一轮任务分别抓 list 和 export；官方 XLSX 作为权威源，归一化 CSV/JSON 从同一工作簿解析，避免重复的外部请求。
6. 已认证的本地 TDC 会话优先复用；密码模式仍不得与浏览器 Cookie/Header 混用，过期后重新认证。

## 验收标准

- 内置任务不会出现“归档取消此任务”；禁用后仍留在列表中且状态更新。自定义任务归档后活动列表不再显示。
- 未配置保护库或引用不受支持时，保存/启用给出可理解错误；不会出现“已设置”但运行时才失败。
- 新手无需编辑 JSON 即可配置每种任务模板的常用筛选条件，旧 JSON 配置仍能读取。
- 目录选择器能选择本地批准根目录或安全子目录；越权、网络和穿越路径被拒绝。
- 重试设置不会把 0 误转成 2；页面显示的数字与实际运行器尝试次数一致。
- TDC 快速查询不等待完整 XLSX；官方精确模式仍与 47 列官方 Excel 契约一致，重复请求在 TTL 内命中缓存。
- 现有全量测试、静态 UI 检查、定时任务生命周期测试和打包检查全部通过；EXE 在无 Python 环境的隔离目录能启动并返回本地首页。
