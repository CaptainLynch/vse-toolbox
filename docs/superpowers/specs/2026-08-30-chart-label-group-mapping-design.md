# 图表标签分组定义（值映射）设计

> 状态：**已确认**（2026-08-30，六项待确认决策全部按文档建议通过：unmatched 默认 keep、组名隐式自归属、精确匹配、≤20 组/≤200 成员、默认科室 tab 不做映射、成员文本框输入）
> 前序：`2026-08-30-ewo-department-default-scope-and-chart-labels-design.md`（标签功能已上线，commit 76ccf6f；标签图渲染缺陷已修复，commit 224b603）

## 背景与目标

科室合并后，EWO 的 `_rsp_smt` 科室列混杂大量新旧科室名（内饰科、内饰工程科、内饰设计科、结构工程科、视觉工程科……）。当前自定义图表标签按原始字段值直接分组，图表条目与新科室分类对不上。本轮需求：**标签支持"分组定义"——把多个原始字段值归并到一个显示组**，例如把 `内饰科、内饰工程科、内饰设计科` 归并为图表条目 `内饰科`，使图表按合并后的现行科室口径展示。

只作用于图表分组展示；不改明细表、不改 summary 统计、不改筛选行为、不写回缓存数据。

## 业界参照（已调研）

三个主流 BI 工具对该需求（维度成员多对一归并）有同构的成熟模式：

| 工具 | 模式 | 关键机制 |
| --- | --- | --- |
| Tableau | Group Your Data | 选中维度成员手动建组 + **Include an "Other" Group** 复选项：未分配成员自动并入"其他"桶；不勾选则未分配成员单独展示 |
| Power BI | Use grouping and binning | Ctrl+多选图表数据点 → Group 合并为新类别（视觉级分组列）；模型级另有 Groups/Bins |
| Metabase | 无直接 UI | 用 `case` 自定义表达式做值映射（`case([科室]="内饰工程科","内饰科",...)`），社区确认这是其惯用法 |

共同的设计共识，本方案直接借鉴：

1. **多对一成员映射**（member → group display name）；
2. **未分配成员必须显式处理**——并入"其他"桶、保持独立展示、或排除，三选一且默认保守（不吞数据）；
3. 映射只影响该图表的展示维度，不回写数据源。

## 选定方案

### 数据模型（复用 app_settings，无迁移）

标签配置 JSON 在既有 `{label, sourceField, sortOrder}` 基础上扩展两个可选键：

```json
[
  {
    "label": "科室",
    "sourceField": "_rsp_smt",
    "sortOrder": 1,
    "unmatched": "keep",
    "groups": [
      {"name": "内饰科", "members": ["内饰科", "内饰工程科", "内饰设计科"]},
      {"name": "外饰科", "members": ["外饰科", "外饰工程科", "外饰设计科"]}
    ]
  }
]
```

- `groups`：有序分组规则数组；缺省 `[]`（行为与现状完全一致，向后兼容）。
- `unmatched`：未命中任何分组的原始值处理方式，`keep`（默认，保持为独立条目）/ `other`（并入"未分组"桶）/ `hide`（从该图表排除）。三者只影响该标签的图表展示。

### 匹配与统计规则（服务层 `_chart_groups_from` 应用）

1. **精确匹配**：原始值 strip 后与成员 strip+casefold 等值即归入该组（中文场景不受大小写影响；不做模糊/通配符/正则，见"否决方案"）。
2. **组名隐式自归属**：原始值恰好等于某组名时归入该组（等价于组名自动成为自身成员），避免 `keep` 模式下出现两条同名条目。
3. **成员不得跨组重叠**：同一原始值出现在两个分组会导致双计，校验阶段直接拒绝（422），不做先到先得的静默消歧。
4. **未命中**按 `unmatched` 处理；`other` 的桶名固定为"未分组"。
5. 每组统计仍为 `{total, completed, incomplete}`，口径与明细/摘要一致（同一默认范围 + 车型过滤），仅分组键经过映射。

### 校验边界（PUT 强制）

- 标签数量上限不变（每交付物 ≤6）；label 规则不变。
- 每标签 `groups` ≤20 条；组名 strip 后 1–40 字符、拒绝控制字符、同标签内唯一；单成员 ≤80 字符；单标签成员总数 ≤200；成员去重、跨组重叠拒绝。
- `unmatched` 仅允许 `keep|other|hide`。
- 校验失败返回 422 脱敏字段错误且不落库（沿用现契约）。

### API（向后兼容）

```text
GET /api/project-status/deliverables/<id>/chart-labels
    data.labels: [{label, sourceField, sortOrder, groups: [{name, members[]}], unmatched}]
    # 旧配置无 groups/unmatched 时返回 [] / "keep"

PUT 同路径
    body.labels 每项可选携带 groups/unmatched；整体替换；校验同上
    （本地写守卫、400/404/422 语义不变）

GET .../analysis
    data.customCharts: [{label, sourceField, groups: {显示组名: {total, completed, incomplete}}}]
    # 结构不变；分组键变为映射后的显示名 → 前端图表渲染零改动
```

### 前端（图表内容设置编辑器）

- 每个标签行增加"分组定义"子区（默认折叠，点"配置分组"展开）：
  - 每条规则一行：`[组名输入框] [成员输入框] [移除]`；成员输入为单个文本框，支持 逗号/中文逗号/顿号/分号 分隔（与待签署人员解析同约定）；
  - "添加分组"按钮；预填已保存规则；
  - 子区底部"未匹配值"三选：保留原样（默认）/ 并入未分组 / 从图表隐藏。
- 保存沿用既有 PUT 整体替换；保存成功后按既有逻辑重载分析面板。
- 图表 tab 渲染逻辑零改动（仍消费 customCharts 的 groups 统计）。

## 否决方案

- **字段级全局映射**（同一字段的所有标签共享一份映射）：定义一次到处复用，但两个标签绑定同字段需要不同归并口径时无法满足；标签数量 ≤6，逐标签配置成本可接受。
- **模糊/关键词匹配**（如"含 内饰 即归并"）：`外饰` 会同时命中 `外饰科`/`外饰工程科`/`外饰设计科` 之外的值（如"外饰造型"），归并结果不可预期；科室合并是有限集合，精确成员清单可核对、可审计。
- **正则/表达式映射**（Metabase `case` 式）：配置门槛高、误配面大、注入风险需要额外约束；本场景不需要。

## 测试与验收（TDD）

- 校验：groups>20、组名重复/超长/控制字符、成员跨组重叠、成员超长、总数>200、unmatched 非法值 → 422/ValueError 且不落库。
- 映射：内饰科三归并用例（`_rsp_smt` 含 内饰科/内饰工程科/内饰设计科/结构工程科 → keep 模式产出 内饰科(合计)+结构工程科+其余独立条目，总数守恒）；other 模式产出"未分组"；hide 模式排除；组名隐式自归属；成员 strip/casefold 匹配。
- 兼容：无 groups 的旧标签行为与统计键完全不变；GET 对旧配置返回 groups=[]/unmatched="keep"。
- API：GET/PUT 携带 groups 的往返；customCharts 分组键为映射后名称。
- 前端契约：编辑器分组子区、成员分隔解析、未匹配三选控件存在；图表渲染断言不变。
- 回归：全量 pytest、node --check、compileall、git diff --check。

## 待确认决策

1. **未匹配值默认行为**：建议 `keep`（未映射科室保持独立条目，总数守恒、不吞数据）。也可选默认并入"未分组"。
2. **组名隐式自归属**：原始值等于组名时自动归入该组（无需把组名重复写进成员清单）——确认该规则。
3. **成员匹配方式**：精确等值（strip+casefold），不做模糊/通配符——确认。
4. **上限**：每标签 ≤20 组、总成员 ≤200——是否合适？
5. **默认"科室"tab 不做映射**：默认科室图来自 summary 的 department_counts；需要归并口径时请新建一个绑定 `_rsp_smt` 的标签替代它（本轮不动默认图）。是否接受？
6. **成员输入交互**：每个分组一个文本框（逗号/顿号/分号分隔多个成员），不做候选值点选（候选来自缓存原始值，数量可能上百）——若你更希望"从下拉勾选缓存中实际出现的值"，请说明，评估后调整。
