# 第三阶段候选包部署与验收手册

适用：本次配套 `VSE-WebUI.exe` 与 `VSE-ExcelWorker.exe`。候选ID、构建和离线结果见同包 `release-manifest.json`、`RELEASE_NOTES.md`；目标环境和第二阶段UI验收仍由用户完成。本手册由Luna/high子智能体起草，主控核对后集成。

## 1. 校验并隔离运行

1. 从候选ZIP解压到新的、可写的独立目录；两个EXE保持同目录。先不覆盖原程序，也不复制真实数据库或凭据进去。
2. 对比同包 `SHA256SUMS.txt` 和ZIP外部校验文件：

```powershell
Get-FileHash -Algorithm SHA256 .\VSE-WebUI.exe
Get-FileHash -Algorithm SHA256 .\VSE-ExcelWorker.exe
```

SHA-256仅验证完整性，不是数字签名。哈希不一致时停止使用。

3. 目录须可写。冻结包优先在EXE旁创建data目录；不可写时可能回退到用户数据目录，**仅改变命令行当前目录不足以隔离数据**。如果实际目录无法确认，停止试运行。
4. 启动WebUI，默认访问 `http://127.0.0.1:5000`；端口被占用时不要结束不明进程。程序支持以本次启动进程的 `VSE_TOOLBOX_PORT` 指定其他端口。
5. 核对版本、候选标识、实际数据目录与配套Worker路径后，再测试合成文件。不要将候选空库误当原有业务库。

Worker帮助入口启动不等于Office业务已可用。Excel处理需要目标机器实际安装且可正常使用Excel；WebUI虽然不包含xlwings，仍含WinHTTP相关COM依赖，不能称为完全无COM依赖。

## 2. 升级前的用户操作

本文档提供步骤，不代表代理已经执行生产升级或获得恢复真实数据的授权。

1. 记录原程序路径、两个EXE哈希、数据库路径及schema、实际数据/导出目录、配置与正在运行的任务。历史 `archiveDirectory` 原值未知时标记待确认，不能把现有pytest临时路径认作正确原值。
2. 停止接收新任务和业务调度，等待现有任务结束，正常退出WebUI与Worker。只处理确定属于本应用的进程；不按名称批量结束Excel或Python进程。
3. 采用经核实的SQLite备份API或一致停机备份方案，保存数据库、必要配置与历史配套程序。运行中的单个.db直接复制不代表一致备份；不能遗漏未checkpoint的WAL内容，不能擅自删除-wal/-shm文件。
4. 记录备份时间、清单和哈希，在隔离副本检查可读性与关键记录。保留原部署目录和唯一原始备份，不覆盖它们。
5. 用户决定正式升级时，明确使用哪份已验证的数据与程序组合。更换到全新目录后不会自动带入原业务数据，不依靠路径猜测完成迁移。

本次离线演练只证明SQLite备份API可恢复合成设置和应用表结构，不证明现场备份已存在或业务数据可以无损恢复。

## 3. 回退规则

回退前停止本应用及调度，保存当前现场。旧程序只有在已确认兼容当前schema时才可读取当前数据库。旧EXE不能直接打开不兼容的新schema；不能只把EXE换回去。

若需要恢复历史数据库，应恢复对应历史程序、配置与一致性备份。覆盖真实库之前由用户明确选择备份并确认：恢复将丢失或需要另行合并备份之后的修改。记录备份时间/哈希、目标schema、影响时段、恢复前现场副本和操作人。

不自动执行降级迁移、删除真实库或猜测恢复archiveDirectory。恢复后先只读核查关键业务记录，再开放写入和调度。

## 4. 目标环境验收记录（全部待用户填写）

共同记录：候选ID；实际Windows版本/架构；Excel版本/位数；测试数据范围；验收人/时间；证据索引。不要记录密码、Cookie或token。验收应使用同一个候选包。

## 5. 完成标准

- M1：候选包已生成，双EXE/ZIP完整性、冻结版本、隔离启动和合成恢复验证有实际证据。
- M2：用户完成同一候选的目标环境与UI验收，阻断项已关闭。

两者分开记录。新缺陷先区分源码、打包与环境；重新构建应使用新候选ID和哈希，并复验受影响链路。候选包不会自动上传、安装、替换生产文件或恢复真实数据。
