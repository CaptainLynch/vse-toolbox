## 已落地

- **诊断贯通**：TDCCrawlerError 提供允许列表控制的结构化诊断，包含来源、操作、报表类型、阶段、关联编号、上游 HTTP 状态、数字业务码、已知响应键及原因是否存在。Web 错误体增加 `error.diagnostic`；既有错误类型及 400/502 状态语义保留。自动下载仍使用 `query_failed`，但历史错误文本保留上述安全元数据，不保存上游自由文本、响应对象或业务记录。
- **嵌套错误摘要**：仅读取顶层 msg/message/error 和一层 error/data 下的 msg/message 标量，脱敏后用于交互提示；缺少原因明确标注。不会将未知对象或堆栈字符串化。JSON 仍不能作为 XLSX 落盘；不把 list 流程数据降级标成官方 Excel 成功。
- **车型名称与 ID 分离**：停止把车型文本直接复制到 `carTypeProjectAll[0]`。查询、全量抓取、导出统一按项目列表精确匹配名称/编号；唯一有效 ID 才能继续。缺失、歧义、失效 ID、ID/名称不匹配明确失败。成功的项目列表仅缓存于本次客户端实例；空车型不查询列表。
- **两个入口支持**：交付物工作台增加手动加载车型列表及选择器，手工改名会清除旧 ID；自动下载的 `carTypeProject` 自动解析，另支持高级字段 `carTypeProjectId`。项目状态连接器也传递该 ID。只有 ID 而没有名称的项目不会把 ID 再当成名称提交。
- **预览体验**：SOR 单独设置 2000px 最小表宽、横向滚动及编号/日期/标题列规则；其它报表不受这些列宽规则影响。保留预览记录实际查询时间和当时筛选，后续导出失败显式标记；更换交付物会清除旧上下文。车型加载响应具备过期请求保护，连接信息变化会清除选中 ID 和选项。

## Gemini 分工与接管

通过用户配置的本地 ZCode launcher，使用 `gemini-3.8-flash-high` 派发两个隔离任务：车型解析及连接器/测试、前端选择器/预览及测试。生产 HAR、数据库和凭据未传给 worker。

两项任务均留下实质性代码和测试后被运行器分类为 `permission` 并停止，未切换 provider。主审读取实际 diff，接管并修正了缺失导入、错误 ID 回退、异步按钮状态、测试执行上下文、窄屏布局等问题，随后独立执行检查。没有把 worker 的成功宣称当作验收证据，也没有扩大运行权限重试。最终代码评审与整体验收由 Codex 完成；没有完成一轮独立 Gemini 最终复审。

本地证据目录：`.runtime/sor-repair/`；worker 原始任务：`.agents/runs/TASK-sor-projects-fix-20260909/`、`.agents/runs/TASK-sor-ui-fix-20260909/`。这些是本机证据，持久结论以本文件为准。

## 生产复测顺序

1. 从新包启动并正常登录。先不填车型，按与此前一致的部门做查询及 XLSX 下载；记录查询与下载各自结果。
2. 加载车型列表并选择目标车型，再分别查询和下载。手工输入应精确匹配车型编号或名称；重名时使用选择器。自动下载保留原 `carTypeProject` 配置即可使用统一解析；如配置内部 ID，应与所选车型对应。
3. 若失败，保留新版页面中的安全错误文本（stage、report、upstream_http、api_code、request_id），以及时间和操作条件。不要直接上传完整登录 HAR、Cookie 或凭据库。
4. 在官方 TDC 网页以同账号、同筛选、相近时间导出：官方也失败时，把安全诊断交上游维护方；官方成功而工具失败时，比较已脱敏的方法、路径、参数名称与 ID/pagePath 语义，做最小协议修复。仅凭 code=1 不猜改请求。
5. 成功验收需同时满足：官方 XLSX 可读取、表头与行数/筛选对照一致；自动下载产生对应文件和快照；没有将失败或部分数据标为成功。
