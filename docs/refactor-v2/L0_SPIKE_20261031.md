## 三个候选窗口方案对比

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| pywebview（WebView2） | 最接近桌面应用（真窗口、可托盘联动、无浏览器壳痕迹）；Win10+ 自带 WebView2 运行时 | 第三方依赖需随包分发（+体积）；`webview.start()` 阻塞需线程化；公司策略对 WebView2 用户数据目录的处理未取证 | **默认首选**（缺依赖自动降级，不阻塞） |
| Edge `--app` | 零依赖（系统自带）；独立 profile 无地址栏；与浏览器安全域一致 | 窗口仍是 Edge 壳；多实例/升级时 profile 目录残留 | **第二级**（现役） |
| 默认浏览器 | 永远可用 | 有地址栏、体验最差 | **兜底**（现役） |

## L0（原生 exe 启动器，如 Tauri/原生 Win32 壳）评估

- 收益：启动更快（省 Python 解释器冷启 1.9s 中的一部分）、窗口体验与更新器解耦。
  （**2026-11-01 复核更正**：1948 ms 是 app 子进程内 `import web.app` 1237.3 + `create_app()` 710.7
  的耗时，不是解释器冷启；本机解释器冷启实测 33–45 ms。见「复核」§5-3、§7。）
- 成本：新工具链（Rust/Win32）、代码签名联动、与 `vse_boot` 双轨维护；本阶段预算应优先
  用户路径补全（W6-W9）与真机验证（W17-02）。
- 触发重评条件：① 真机实测三级回退在目标办公电脑全部不可用（极小概率）；
  ② pywebview 在生产机被安全策略拦截且 Edge app 体验投诉集中。

### 3. 单实例现状

- 锁：`InstanceLock`（390-431），路径 `state/instance.lock`（`vse_boot/layout.py:61-62`）；
  Windows 用 `msvcrt.locking(LK_NBLCK, 1)` 非阻塞独占 1 字节，POSIX 用 `flock`。
- 主实例：`Supervisor.run`（465-478）拿到锁后把 `_lock_key(lock.path)` 记入 `_OWNER_LOCKS`（371），
  退出时移除并删 `instance.json`（476-477）。
- 第二实例：`run` 拿不到锁 → `_show_existing`（480-487）读 `state/instance.json`
  （`layout.py:49-50`）里的 `url`，调 `show`（默认 `open_window`，见 442）后返回 0；
  **不起第二份 app**。文件缺失/损坏时只记「正在启动，请稍候再打开」并返回 0（485-487）。
- job 归属（47 新增）：`open_window` 的 `assign_job` 默认由
  `launcher_holds_instance_lock(layout.lock_file)`（381-387）判定——只有长驻启动器把窗口
  收进 `_KillOnCloseJob`；第二实例 `assign_job=False`，`spawn_window` 不调 `_JOB.assign`（274-275），
  否则 `KILL_ON_JOB_CLOSE` 会在它退出时杀掉刚开的窗口。
- 作用域（本轮补的边界事实）：锁挂在**安装根**下，所以单实例语义是「每个安装根一个实例」；
  两个不同安装根（例如便携目录 + `%LOCALAPPDATA%`）可以同时各跑一份。REQUIREMENTS A3 的目标
  写法是「命名互斥量」，现状是文件锁——两者不完全等价；**本轮不改**，记录给 02/03 或 L0 决策。

### 4. 端口现状

- 选端口：`free_port()`（59-62）绑 `127.0.0.1:0`；`port_is_free(port)`（65-71）探测占用。
- 冲突判定两处：`_boot` 的 **spawn 前**（544-546）与**子进程早退时**（570-574）——后者要求
  `child.poll() is not None` 且端口已不空闲，才判 `port_conflict`；两条路径都**不记 `bootFailed`、
  不 `abandon` 试用版本**（574 之后才是失败分支）。
- 重试：`_loop`（516-526）换端口重来，`_MAX_PORT_RETRIES = 3`（41），超限返回 3 并给中文提示
  （520-522）；`first = True` 让新端口重新开窗（524）。
- 沿用端口：`restart` 分支（527-529）不改 `port`，已打开的窗口刷新即可继续用；
  `_serve` 只在 `open_window` 标志为真时开窗（616-617），所以重启不重复开窗。
- 探活：`probe_app`（177-186）同时探 `/api/version` 与 `/api/host/manifest`；
  `_wait_healthy`（596-605）上限 `HEALTH_TIMEOUT_SECONDS = 45.0`。

### 6. 与 DSH-V2-47 的实现边界

**47 已做的修复（本轮只复核，不重复实现、不改代码）**

1. pywebview 移出启动器进程：`spawn_window` + `--window` 子进程 + `run_window` 主线程
   （`vse_boot/__main__.py:132-136`）。
2. `open_window` 立即返回；15 s 宽限期内非 0 退出或 spawn `OSError` 才降级；监视线程非 daemon。
3. 第二实例窗口不挂其 job（`assign_job` 由 `launcher_holds_instance_lock` 判定）。
4. 端口冲突零干预：spawn 前 + 早退后两处判定，换端口 ≤3 次，不记 `bootFailed`。
5. 窗口子进程 stderr 抹 URL（252-254）。

**不是 47 的、也不是 L0 能带来的（归 02/03）**

- URL 带 `?boot=` 票据进入窗口子进程命令行（269-272）与 Edge 命令行（359）——本机进程列表可见。
- `instance.json` 明文 `bootToken`（613-615）。
- 二者属票据/本机安全契约范围；`docs/refactor-v2/DSH_LOCAL_SECURITY_CONTRACT.md` **不在本基线**，
  本报告不引用其内容。

**只有 L0 才能带来的改变（相对 47 后的现状）**

- 启动器外层进程身份：从 PyInstaller onedir bootloader 换成自建原生 stub（`ARCHITECTURE.md` §5.2
  第 159 行：L0 用 `runtime\pythonw.exe` 起 `vse_boot`），从而改变杀软误报画像
  （`ARCHITECTURE.md` 第 151 行把「`pythonw.exe` 带 PSF 官方签名，比自建未签名 bootloader
  更少触发杀软误报」列为选型理由）与固定路径/开始菜单语义。
- L0 自更新的改名机制（`ARCHITECTURE.md` 第 128 行）。
- **不能**带来：三级回退行为、单实例语义、端口零干预、试用/回滚正确性——这些已在 L1 `vse_boot`
  内实现并有测试；窗口与托盘也在 L1。

### 7. L0 收益 / 成本 / 重评触发条件（2026-11-01 更新）

**收益（可量化部分已收窄）**

- 启动耗时：上限是启动器 stub 自身开销；**不含**解释器冷启（33–45 ms），更不含 app 冷启
  （1948 ms，发生在 app 子进程内，任何 L0 方案都无法消除）。
- 分发与信任：原生签名 stub 取代自建 bootloader，降低杀软误报；固定路径/快捷方式更稳定。
- 解耦：窗口/更新器与启动器解耦（设计目标，非当前痛点）。

**成本**

- 新工具链（Rust 或 C/Win32）+ 代码签名联动 + 与 `vse_boot` 双轨维护。
- L0 自更新的 `.old` 改名流程、崩溃/半更新状态的恢复路径需重新验证。
- 单实例若改为命名互斥量，需与现有 `InstanceLock`（文件锁、按安装根）迁移对齐，属公共契约变更，
  须主控决策。

**重评触发条件（原 ①② 保留，新增 ③④⑤）**

1. 真机实测三级回退在目标办公电脑全部不可用。
2. pywebview 在生产机被安全策略拦截且 Edge app 体验投诉集中。
3. 目标机出现 `VSE-Toolbox.exe` 被杀软误报/拦截的可复现报告。
4. 实测启动器 stub 开销在目标机占比显著（须先在打包产物上量出 stub → `vse_boot` 起点的耗时；
   本轮无该数据）。
5. 出现「窗口必须由启动器进程直接持有」的硬需求（例如托盘最小化到托盘、单进程窗口生命周期管理），
   使「窗口子进程 + 监视线程」方案不再够用。

> 任一条件成立时，重评的议题仍是「是否替换」，不以「已决定替换」为前提；本轮结论不变：**不替换**。
