# VSE Toolbox v2 重构架构方案

> 分支：`refactor/ux-v2`（基于 `feat/d5-arch-part-attribution@e4c181e`）· 起草：2026-10-28 · 状态：**待评审草案**
> 配套文档：[功能需求清单与方案](REQUIREMENTS.md)

## 0. 一句话目标

让不懂代码的普通工程师：**下载 → 解压 → 双击 → 登录一次 → 选项目 → 每天直接看结果/发报告**；
让维护者：**改一行业务代码 → 发一个几百 KB 的签名补丁 → 同事双击即生效，出错自动回滚**。

## 1. 约束（全部为硬约束）

| # | 约束 | 对架构的直接影响 |
|---|---|---|
| C1 | 生产电脑**无管理员权限** | 只能装到 `%LOCALAPPDATA%`；不能写 `Program Files`、HKLM、系统服务；文件关联/自启只用 HKCU 或「启动」文件夹 |
| C2 | **未装 Python** | 运行时必须随包自带，且不依赖 VC++ 运行库安装器（需随包附带 DLL） |
| C3 | 更新**只能经飞书/QQ 发文件**（只是传文件的渠道；产品内不集成飞书，见需求清单 K6） | 没有服务器、没有共享盘 → 不能做自动下载；补丁必须**小**（QQ 实测 9.2 MB 可发、20.3 MB 失败），且接收后要**一步安装** |
| C4 | 普通办公电脑：Win10/11，可能有杀软、SmartScreen、组策略 | 尽量少引入新的未签名 exe；外部依赖（WebView2）必须有退路 |
| C5 | Excel 功能依赖本机已激活的 Excel（COM） | Excel 能力保持进程外 Worker，自动启停 |
| C6 | 用户同时跟**多个项目**，需要切换 | 项目成为一等实体，主计划/同步配置/报告都按项目隔离 |
| C7 | 形态：**桌面窗口 + 托盘** | 不再有黑色控制台窗口；关窗不退出，后台继续同步 |

## 2. 现状诊断（代码事实）

| 事实 | 证据 | 后果 |
|---|---|---|
| 业务逻辑集中在宿主 | `web/app.py` 7,162 行、约 100 条路由；`services/` 约 3.3 万行 | 插件只是"前端壳"：9 个插件里只有 sign_daily/tir_report/project_overview/deliverable_forms 有自己的路由，其余 `backend.py` 仅 12–14 行 |
| 宿主代码被 PyInstaller 冻结进 exe | `VSE-WebUI.spec` → onedir，业务 `.py` 编进 PYZ | **任何 services/core 修改都要重发 42.5 MB 整包**，QQ 发不出，需三分卷 |
| 插件增量更新已有雏形 | `host/updates.py`：Ed25519 签名 `.vsepkg`、暂存→重启生效→失败自动回滚 | 机制可复用，但只覆盖 `plugins/`，覆盖不到真正经常改的 `services/` |
| 数据目录在 exe 旁边 | `<exe>\data\`，升级要手工把 `data` 移到新文件夹（运维指南 §7.3） | 升级步骤对普通用户不可完成 |
| 主计划是单项目模型 | `project_status_phases` 等表无 `project_id` | 多项目切换需要数据模型迁移 |
| 前端无构建步骤 | `web/static/host/vendor/preact-htm.js` + ES module | **保留**：静态文件天然可按文件增量更新 |

**核心结论**：现在"更新难"的根因不是插件机制不够，而是**经常变化的代码（业务逻辑）被放在了最难更新的位置（冻结的 exe 里）**。v2 的第一原则：**按变化频率分层，变化越频繁的层越容易单独替换。**

### 3.1 安装目录布局（全部在用户目录，无需管理员）

```
%LOCALAPPDATA%\VSE-Toolbox\
├─ VSE Toolbox.exe            L0 启动器（固定路径，开始菜单/桌面快捷方式指向它）
├─ runtime\
│   └─ rt-2026.11\            L1：python 嵌入版 + site-packages + DLL
├─ app\
│   ├─ 2.0.3\                 L2：内核 .py + shell 静态文件
│   └─ 2.0.2\                 上一版（保留用于回滚）
├─ packs\
│   └─ <pack-id>\<version>\   L3：功能包（随 app 内置的版本 + 补丁安装的版本）
├─ state\
│   ├─ active.json            当前生效的 runtime/app/各 pack 版本 + 上一版本
│   ├─ staging\               已校验、待重启生效的补丁
│   └─ events.log             安装/回滚记录（用户可见的「更新记录」）
└─ data\                      数据库、归档、下载、日志（永不随升级移动）
```

- 首次运行：若检测到旧版 `<exe旁>\data\`，向导一键**复制**到新位置（原地保留旧副本，成功后提示可删）。
- 用户也可以把整个目录放在 U 盘/其他盘：启动器以自身所在目录为根（便携模式），`%LOCALAPPDATA%` 只是默认值。

## 4. 增量更新设计（需求 1 的核心）

### 4.1 统一补丁格式 `.vsepkg` v2

沿用现有 Ed25519 签名与 sha256 清单（`host/updates.py`），扩展字段：

```json
{
  "format": 2,
  "kind": "pack | app | runtime | bundle",
  "id": "sign-daily",              // kind=app 时为 "app"，runtime 为 "runtime"
  "version": "0.3.1",
  "requires": {"app": ">=2.0,<3", "runtime": "rt-2026.11 (py3.12)"},
  "files": {"backend.py": "<sha256>", "static/report.js": "<sha256>"},
  "migrations": ["0007_add_watchlist_project_id"],
  "notes": "签署日报：修复周末不计天数的问题"
}
```

- **app/pack 一律发全量包，不做文件级差分**（评审 R1）。实测：`core+services+host+web+plugins` 全部源码与静态文件 gzip 后约 **0.85 MB**，一个 app 全量包就小于 1 MB，单个功能包通常只有几十 KB。全量包不存在"基线版本不匹配"的问题，用户跳过几个版本也能直接装最新版。"增量"体现在**分层**上：日常只发 app 或 pack，不必再发 runtime。
- **bundle**：一个文件里装多个包（如 app + 2 个 pack 同时升级），按依赖顺序安装，**全成或全不成**。
- **体积预算**：app/pack/bundle 硬上限 8 MB（低于 QQ 实测可发的 9.2 MB），发布工具超限即报错。只有 runtime 会超限，按需分卷（通常经飞书发送，一年发 1–2 次）。
- `.pyc` 与 Python 小版本绑定：`requires.runtime` 必须写明 Python 版本，不匹配时拒绝安装（评审 R12）。

### 4.2 用户侧：一步安装（适配"只能飞书/QQ 发文件"）

三条入口，用户用哪条都行：
1. **自动发现（推荐，零操作）**：程序启动时和托盘常驻期间，扫描「下载」文件夹，以及用户在设置里添加的文件夹（例如聊天软件的接收文件夹；程序不内置任何聊天软件的路径，也不集成任何聊天软件）（**只匹配 `.vsepkg` 文件名，不读取其他文件**；可在设置里关闭）。发现新的、签名有效的包后，托盘弹出提示，**由用户点击确认后才安装，绝不静默安装**（评审 R7）：「发现更新：签署日报 0.3.1（修复周末计天）— [立即更新] [稍后]」。
2. **双击补丁文件**：首次运行时在 **HKCU** 注册 `.vsepkg` 文件关联（不需要管理员），双击后直接进入安装确认页。
3. **拖进窗口**：主窗口任何位置都接受拖入。

安装流程：L2 内的更新管理器校验签名和依赖 → 解压到 `state\staging` → 「需要重启生效，[现在重启]」→ 下次启动时 L2 引导脚本把 staging 中的内容移入版本目录，并把新版本写成"试用中" → 健康检查 → 通过后转为"已生效"；不通过就**自动切回上一版本**，并在「更新记录」里写明原因。

### 4.3 版本切换与回滚

职责划分（评审 R4）：**签名校验、解包、迁移全部由 L2 的 Python 引导脚本完成**（`cryptography` 已在运行时中）。L0 只负责三件事：读 `active.json` 选目录、启动、在启动超时时切回 `previous`。这样 L0 才能做到真正"几乎不变"。

- 版本切换**只在启动时**做，运行中绝不替换文件（沿用现有规则）。
- **健康检查**：新版本启动后 30 秒内必须完成"内核就绪 + 所有包加载成功 + 首页接口 200"。不达标就回滚；L3 包级别的失败只回滚该包。
- **数据库保护**（评审 R2）：补丁包含迁移时，迁移前先做一致性快照（SQLite backup API），保留最近 3 份。**只有**在新版本还处于"试用中"（健康检查未通过）时回滚，才连同快照一起恢复；新版本已生效后用户手动回滚时**不恢复快照**，以免丢掉升级后同步到的数据。这依赖下一条规则保证旧代码能读新库。
- 迁移只允许**增量**（加表/加列/加索引），沿用 `host.migrate([(version, fn)])`；破坏性变更必须拆成"新增 → 双写 → 下个大版本再清理"。
- **L0 自身的更新**：随 app 包下发新的启动器文件；L2 在退出时把正在运行的 `VSE Toolbox.exe` 改名为 `.old`（Windows 允许改名正在运行的 exe），再放入新文件，下次启动时删除 `.old`。

### 4.4 维护者侧：一条命令发布

`python tools/release.py --since v2.0.2`：
1. 根据 git diff 判断哪些层变化（runtime 依赖锁文件 / app 内核 / 哪几个 pack）；
2. 自动提升版本号，生成 app/pack 全量包（或打成 bundle）；依赖锁文件有变化时，额外生成 runtime 包；
3. 签名，检查体积预算，生成面向用户的「更新说明」（取自提交信息中的 `用户可见:` 段）；
4. 把产物放到 `dist/releases/<日期>/`，并打 git tag。私钥仍只放在打包机（沿用 `tools/plugin_keys.py`）。

### 4.5 什么时候才需要大包

| 变化 | 发什么 | 体积量级 |
|---|---|---|
| 某个功能包的业务/页面 | pack 全量包 | 10–500 KB |
| 内核、UI Kit、术语表 | app 全量包 | ≈1 MB |
| 新增/升级第三方依赖、换 Python 版本 | runtime 全量（飞书发，可按需分卷） | 25–40 MB |
| 启动器自身 | 新安装包（极少，设计目标是一年不变） | — |

## 5. 运行时与启动（适配"无管理员 + 无 Python"）

### 5.1 L1 运行时：Python 官方嵌入版（embeddable）+ 预装依赖

- 选择嵌入版而不是 PyInstaller 冻结，原因：业务代码以普通 `.py` / `.pyc` 存在于 `app\` 和 `packs\` 中，**可以按文件替换**；不会出现 PyInstaller 静态分析漏收模块（现有 spec 里已经在手工补 `hiddenimports`）；`python.exe`/`pythonw.exe` 带 PSF 官方签名，比自建的未签名 bootloader 更少触发杀软误报。
- 依赖用 `pip install --target` 预装到 `runtime\rt-x\Lib\site-packages`，随包附带 VC 运行库 DLL。pywin32 的 `pywin32_system32` 需要在引导脚本里 `os.add_dll_directory`（**Spike S1** 验证）。
- **可选**：发布时把 `.py` 编译成 `.pyc`（不保留源码），减少同事误改。

### 5.2 L0 启动器

- 体积小、几乎不变的原生 exe（Spike S2：在 Go 单文件 exe 和 PyInstaller onefile 极简脚本之间二选一，以杀软误报率和体积为准）。
- 职责只有：**单实例**（命名互斥量；再次双击 = 唤起已有窗口）→ 读 `active.json` → 用 `runtime\pythonw.exe` 启动 `app\<ver>\bootstrap.py` → 等待健康信号 → 超时则切回 `previous` 再启动一次。补丁的校验和应用不在 L0 中做（见 §4.3）。
- 首次运行时，在用户自己的开始菜单和桌面创建快捷方式，在 HKCU 注册 `.vsepkg` 关联；「开机自启」开关写 HKCU `Run` 键，默认关闭，首次向导里询问。全部不需要管理员。

### 5.3 桌面窗口与托盘

- 窗口用 `pywebview`（EdgeChromium/WebView2 后端）；托盘用 `pystray`。
- **退路**：WebView2 Runtime 缺失或被策略禁用时，自动改用 `msedge --app=<url>` 打开无地址栏窗口（Win10/11 自带 Edge）；Edge 也不可用时，最后用默认浏览器打开。三种方式由同一个前端提供服务，用户无感（Spike S3：确认公司电脑的 WebView2 覆盖率）。
- 关窗 = 隐藏到托盘，后台同步、归档、日报继续运行；托盘菜单：打开 / 立即同步 / 更新记录 / 退出。
- 本机服务只监听 `127.0.0.1` 的随机端口，每次启动生成会话令牌：启动 URL 带一次性 fragment 令牌，前端首次加载时用它换取 HttpOnly + SameSite=Strict 的 cookie，随后令牌作废（评审 R5：这样 WebView2、Edge `--app`、默认浏览器三种退路都适用）。其他本机进程和浏览器标签页无法调用写接口（强化现有的 `local_guard`）。
- 调度器跑在托盘进程里：用户从托盘「退出」时，提示"退出后不会自动同步"；首页显示「上次后台运行时间」（评审 R9）。
- Excel Worker 改为由同一运行时的 `python.exe` 启动子进程，替代现在的 `VSE-WebUI.exe --excel-worker` 哨兵（评审 R10）。

### 5.4 后台任务不再依赖 Windows 计划任务

现有的 `tools/install_*_task.ps1` 需要用户手动执行 PowerShell，部分电脑还会被策略拦截。v2 中调度器跑在托盘进程里（内核的调度服务），开机自启由 HKCU `Run` 承担；电脑睡眠时错过的任务，醒来后补跑一次。

## 6. 应用分层与模块边界

### 6.1 L2 内核：只提供"平台能力"，不含业务

| 内核服务（HostContext） | 说明 | 来源 |
|---|---|---|
| `db` + `migrate` | SQLite 连接、按包前缀的增量迁移、迁移前快照 | `core/db_manager.py`、`core/repos/plugin_schema.py` |
| `identity` | 统一域登录、Aras/TDC 会话、DPAPI 凭据库、会话过期事件 | `core/domain_identity.py`、`core/credential_provider.py`、`services/*_auth.py` |
| `projects` | 当前项目、项目列表、项目切换事件（**新**） | 新建 |
| `tasks` | 统一任务中心：提交、进度、取消、重试、产物、7 天清理 | `services/crawl_task_runner.py` |
| `scheduler` | 周期任务注册（同步/归档/日报/TIR），补跑，暂停 | 合并 project_status 调度与 scheduled_archive 调度 |
| `archive` | 原子归档存储与保留期 | `core/archive_store.py` |
| `excel` | Excel Worker 自动启停、白名单根目录 | `core/excel_*`、`services/excel_*` |
| `notify` | 托盘气泡与页内通知（同步失败、更新可用、日报生成完成） | 新建 |
| `glossary` | 术语与文案表（zh-CN），包可以覆盖或扩展 | 新建 |
| `diagnostics` | 诊断录制、一键导出诊断包 | `core/diagnostic_recording.py`、`core/debug_bundle.py` |
| `updates` | 补丁发现、校验、暂存、状态 | `host/updates.py` 升级为 v2 |

**规则（沿用并收紧）**：包只能经 `host.context` 使用内核，不能 `import` 其他包；包之间需要的数据通过内核的**只读查询接口**或**事件**获取（例如签署日报读取关注清单，走 `deliverables` 包注册的 `watchlist` 查询，不直接读表）。

### 6.2 L3 功能包：后端 + 服务 + 页面 + 迁移 + 文案，一起发版

```
packs/sign-daily/
├─ pack.json          id、版本、requires、导航入口、页面、权限、定时任务声明
├─ backend.py         register(host)：路由
├─ service/…          业务逻辑（由 services/ 迁入）
├─ migrations.py      [(version, fn)]
├─ static/…           页面（preact-htm，无构建）
└─ glossary.json      本包的用户文案
```

现有 `services/` 按领域拆分到对应的包：Aras 客户端、TDC 客户端、表单解析这类**被多个包共用**的集成代码，单独作为 `connector-aras` / `connector-tdc` / `forms-core` "库包"（只注册服务、不出页面），可以独立更新。
**库包不允许被 `import`**（评审 R3，与 §6.1 规则一致）：库包在 `register(host)` 中执行 `host.provide("aras", AraClientFacade)`，使用方在 `pack.json` 中声明 `"uses": ["aras"]`，运行时通过 `host.use("aras")` 获取对象。注册表按声明校验接口版本，缺失时该包显示「需要先更新 xx」，不会让整个程序崩溃。

### 6.3 前端：保留无构建 ES Module，重做外壳与信息架构

- 新导航（详见需求清单 UX 部分）：**今天 / 项目 / 报告 / 工具 / 设置** 五个入口，外加顶部的项目切换器；专家功能统一收进「设置 → 专家模式」开关之后。
- UI Kit 新增：`Wizard`（分步向导）、`FixIt`（待配置项旁的"去修复"按钮，直接打开对应表单）、`ErrorCard`（发生了什么 / 你需要做什么 / [一键处理] / [导出诊断包]）、`Skeleton`（骨架屏）、`ExpertOnly`（专家模式可见的包装器）、`StatusPill`（统一状态色：只有真正产出数据时才显示绿色）。
- 所有用户可见文字经 `t('key')` 取自术语表，**改文案 = 发一个几 KB 的包**。
- 静态资源按版本目录提供，URL 带版本号，从根上解决"代码改了界面没变"的缓存问题（目前靠 `Cache-Control: no-cache` 兜底）。

## 7. 数据模型变化

1. **项目一等化（C6）**：新增 `projects_v2`（id、代码、名称、车型列表、默认科室、归档状态），给 `project_status_phases / milestones / deliverables / update_bindings / sync_runs`、关注清单、签署日报配置、TIR 配置补 `project_id`。迁移时把现有数据挂到自动创建的"默认项目"下。**这是高风险迁移**：先加列并回填，读路径按 `project_id` 过滤，旧接口默认使用当前项目；必须有回滚快照和对拍测试。
2. **筛选条件结构化**：同步、归档、日报的筛选从自由 JSON 改为每个连接器声明的字段规格（字段、类型、候选值来源、默认值），前端据此自动渲染表单。存储仍是 JSON，但只能经过规格校验写入。这与 2026-10-27 评审中"`MatchFieldSpec` 声明化"的提议是同一方向，可以合并实施。
3. **按项目推导默认配置**：项目里填了车型代码和科室，就自动生成各交付物的默认筛选、外部稳定键候选和字段归属，用户只需点「确认」。映射取证（2/2 一致）在后台自动跑，界面只展示"已核对 ✓"。

## 9. 风险与待验证项

| 风险 | 级别 | 缓解 |
|---|---|---|
| 嵌入版 Python 下 pywin32/xlwings 的 COM 注册与 DLL 路径 | 高 | Spike S1；失败时退回"PyInstaller 冻结 L1 依赖 + 业务代码外置 sys.path"的方案（同样可增量，只是更容易漏收标准库模块，需要 `--collect-all` 标准库） |
| 公司杀软拦截新的启动器 exe | 中 | S2 实测；必要时申请代码签名证书；启动器几乎不变，只需要过一次白名单 |
| WebView2 被策略禁用 | 中 | Edge `--app` → 默认浏览器，三级退路 |
| 多项目迁移导致数据错挂 | 高 | 迁移前快照、默认项目回填、对拍测试、可回滚；这一步单独 PR，单独评审 |
| 自动扫描下载目录被视为隐私问题 | 低 | 只看文件名后缀 `.vsepkg` 和签名，不读其他文件；设置里可以关闭 |
| `.pyc` 与运行时 Python 版本不一致 | 中 | `requires.runtime` 写死 Python 版本；发布工具用运行时自带的解释器编译 |
| 私钥泄露 | 高 | 沿用：私钥只留在打包机；支持多公钥轮换（`host/trusted_keys.json` 随 app 更新下发） |

## 10. 待你拍板的问题

1. **CLI 下线会连带移除仅 CLI 才有的功能**：「扫描飞书待办」已决定随飞书功能一起下线（2026-10-28，见需求清单 K6）；剩下的「生成周报 PPT」「内网抓取（selenium）」是否确定不再需要？如果需要，会作为功能包迁进新界面。

## 11. 评审记录（2026-10-28，第 1 轮）

评审方式：逐节对照代码事实（`host/updates.py`、`VSE-WebUI.spec`、`requirements.txt`、`core/db_common.py`、插件 `backend.py` 路由统计）与 §1 的硬约束 C1–C7。

| # | 发现 | 严重度 | 处置 |
|---|---|---|---|
| R1 | 文件级差分机制带来"基线错配"复杂度，但实测全部 app 代码 gzip 后只有约 0.85 MB，差分没有收益 | 重大简化 | §4.1 改为 app/pack 一律发全量包；增量体现在分层上 |
| R2 | 回滚时恢复数据库快照，会丢掉升级后同步到的数据 | 高 | §4.3：只在"试用中"失败时恢复快照；已生效后的回滚不恢复，依赖"只增量迁移" |
| R3 | "包不能互相 import"与"连接器库包"相互矛盾 | 中 | §6.2：改为 `host.provide/use` 服务注册 + `pack.json` 声明 `uses` |
| R4 | L0 承担签名校验和解包，会迫使启动器经常更新 | 中 | §4.3/§5.2：校验和应用移到 L2 引导脚本；补充 L0 自更新的改名方案 |
| R5 | 在 Edge `--app` / 默认浏览器退路下，无法向窗口注入令牌 | 中 | §5.3：一次性 fragment 令牌换取 HttpOnly cookie |
| R6 | `selenium` 只被 `services/intranet_scraper.py`（CLI 功能）使用；`rich` 只被 CLI 使用 | 低 | `imapclient` 随飞书功能下线确定移除（K6）；CLI 下线后再去掉 selenium/rich。若 §10-1 决定保留周报 PPT 或内网抓取，再重新评估 |
| R7 | 自动扫描下载目录可能被理解为静默安装或隐私问题 | 低 | §4.2：只匹配文件名，必须用户确认后才安装，可以关闭 |
| R8 | D2「按项目推导默认配置」依赖项目实体，但原计划放在项目实体之前的 M2 | 中 | §8：M3 中项目实体先行，D2 随后 |
| R9 | 调度器在托盘进程内，用户退出后不会同步，但界面上看不出来 | 低 | §5.3：退出时提示 + 首页显示「上次后台运行时间」 |
| R10 | 现在 Excel Worker 依赖冻结 exe 的 `--excel-worker` 哨兵，嵌入版下不再适用 | 中 | §5.3：改为同一运行时的 `python.exe` 子进程 |
| R11 | `.vsepkg` 补丁是否会触发 SmartScreen | 信息 | 不会：补丁不是可执行文件，只有首包里的启动器需要过一次 |
| R12 | `.pyc` 与 Python 小版本绑定 | 中 | §4.1 `requires.runtime` 写明 Python 版本；§9 补充风险 |

**结论：有条件通过。** R1–R12 已修订进正文。剩余前置条件是 M0 的四项 Spike（尤其是 S1 嵌入版 COM、S3 WebView2 覆盖率），它们只能在生产同型机上验证，结果可能改写 §5。§10 的 4 个问题不影响 demo 和 M0，可以与 M0 并行确认。
