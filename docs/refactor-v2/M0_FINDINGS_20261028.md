# M0 生产环境采集结论（第 1 批，2026-10-28）

> 来源：`tools/env-probe` probe 1.0 在 1 台生产办公电脑上的运行结果 + 问卷（原件在 `.runtime/env-probe/results/01-self/`，不进 git）。
> **样本量 = 1 台**，且是目前唯一的用户。推广到约 20 人之前，至少再用 probe 1.1 采集 2 台其他科室的电脑（见 §4）。

## 1. 环境事实

| 项 | 结果 | 备注 |
|---|---|---|
| 系统 | Windows Enterprise LTSC 2024（build 26100.7462，24H2 内核），x64，32 GB 内存 | 注册表 ProductName 显示 "Windows 10"，这是 LTSC 2024 的已知现象；从 build 号看实际是 Win11 内核 |

| 用户目录运行程序 | ✅ 可运行（用系统 whoami.exe 实测） | 没有 AppLocker 规则；存在 SRP（Safer）注册表项，但没有拦截 |

| 杀毒软件 | McAfee Endpoint Security | 用户已经在直接运行未签名的 PyInstaller exe（13 个副本），说明未签名 exe 至少在这台电脑上没被拦截 |
| WebView2 | 本机级安装 **122.0.2365.106**；Edge 144 | WebView2 版本停留在 2024 年初，可能已停止自动更新，但版本足够 pywebview 使用 |

| .NET Framework | 4.8.1（release 533320） | |
| Python | 没有 | 符合约束 C2 |
| Office | Office 2021 ProPlus（批量授权）**x64**，Click-to-Run 16.0.14332；Outlook 已安装 | |

## 2. M0 四项前提的判定

| Spike | 判定 | 依据 | 还缺什么 |
|---|---|---|---|
| S1 嵌入版 Python + COM | **基本成立** | Office x64 → 运行时采用 **x64 Python**，不需要 x86 版本；COM 可用 | 用嵌入版 Python + pywin32 实测一次（M0 剩余工作，可以在开发机上用 x64 Office 先验证） |
| S2 启动器与杀软 | **成立（样本 1）** | 用户目录可以运行程序；没有 AppLocker；McAfee 放行了未签名的 PyInstaller exe | 用未签名的启动器原型在这台电脑上实测；代码签名证书（B3：不知道）先不作为前提 |
| S3 WebView2 | **成立** | 本机级 WebView2 122 + Edge 144，两级退路都在 | 用 pywebview 在 WebView2 122 上打开一次 demo |
| S4 补丁往返 | **成立** | HKCU 可写（双击安装、自启）；飞书默认保存到「下载」（B2「默认文件夹」+ 实际 13 个副本都在「下载」里） | 真实发送一次补丁包，完成"飞书下载 → 自动发现 → 安装 → 回滚" |

## 3. 问卷带来的设计变更

| 问卷 | 事实 | 设计变更 | 落在 |
|---|---|---|---|
| A1 | 现在 1 人使用，测试通过后推广到约 20 人 | 首次使用向导和自动更新是推广的前提，M1/M3 不能省 | 架构 §8 |
| A2 | 每人跟 3 个左右项目 | 项目切换器是 P0（已在方案中） | 需求 C1 |
| A3/A4 | 最常用：项目状态 → 交付物同步 → 签署日报；**从不用自动归档** | 自动归档**不再作为独立功能**：每次同步时自动留存原件（就是归档），界面上只在交付物详情显示「历史原件」 | 需求 G、导航 |
| A5 | 每天 8:30 使用 | 签署日报默认在工作日 08:30 自动生成；首页「今天」按 8:30 场景设计 | 需求 F3 |
| A6-1 | **每次都要重新登录** | 提升为 P0 头号问题：默认保存凭据（DPAPI），会话过期时静默续期，只有在密码变更时才打扰用户 | 需求 B3/B4 |
| A6-2 | **数模审批流程不能正常同步** | 现网缺陷，需要单独排查（不等 v2）；v2 中同步失败必须显示 ErrorCard，并给出原因 | 单独任务 |
| B1/B2 | 用飞书传文件，保存在默认的「下载」文件夹 | 自动发现默认只监视「下载」即可覆盖；飞书单文件上限远大于 QQ，runtime 包**不再需要分卷** | 架构 §4 |
| B5 | 电脑晚上会关机 | 不能依赖夜间同步：改为**固定时刻 + 开机补跑**，当天错过的时刻在开机后补跑一次 | 需求 D4 |
| C1 | 48 个车型代码（含 6 个 Ar- 平台） | 车型选择改为**可搜索的下拉框**，按项目预选；Ar- 平台单独分组 | 需求 D3、U |
| C2 | 实际要看的科室：车体科、车身科、内饰科、外饰科、车体架构集成科 | 作为默认科室集合（与现有"默认五科室"一致） | 需求 D3、F1 |
| C3 | TIR 只按车型筛选 | TIR 页面只保留车型一个条件 | 需求 F4 |
| C4 | 所有交付物每天 09:00、16:00 各同步一次 | 默认调度从"每 15 分钟"改为**每天 09:00、16:00 + 开机补跑**，可以增删时刻 | 需求 D4 |
| D1/D2 | 周报 PPT、内网抓取**不要了** | K1 全部下线；运行时去掉 selenium / rich / imapclient；`services/office_toolbox.py` 的 PPT 生成和 `intranet_scraper.py` 随 CLI 移除 | 需求 K1、架构 §10 |
