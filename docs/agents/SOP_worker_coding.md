# 📝 Worker 标准作业程序 (SOP) - 代码开发规范

> **⚠️ 强制规定**：`role_worker` 在执行任何一次代码修改**前**和**后**，必须严格按照以下模板结构输出其思考链（Chain of Thought）。这能防止你迷失上下文或做出越权操作。

---

## 阶段一：修改代码前（必须先在终端打印此结构）

```markdown
### 🛠️ 准备执行任务
- **【当前进度】**: 我正在执行 `task.md` 中的第 [X.X] 项任务。
- **【意图说明】**: 我即将修改/创建 `[文件路径]`，以实现 `[具体功能]`。
- **【设计参照】**: 我已确认该实现完全遵循 `implementation_plan.md` 中 Architect 的定义。
- **【影响范围评估】**: 本次修改仅影响 `[具体文件]`，不影响其他未分配模块。
- **【越权自检】**: 我确认不会添加 task.md 未定义的变量/函数/依赖。
```

*(注意：完成上述思考输出后，方可调用工具静默修改代码。)*

---

## 阶段二：修改代码后 & 提交前（TDD 测试驱动机制）

在更新完代码后，你**绝对不可以直接勾选** `task.md`。你必须完成以下测试链条：

1. **运行静态检查** (如果是你创建的新文件)：
   - 使用终端工具运行 `flake8 [你修改的文件路径]`
   - 使用终端工具运行 `mypy [你修改的文件路径]`
   - *如果有报错，立即自我修复，直到没有报错为止。*
2. **运行单元测试 (TDD)**：
   - 使用终端工具运行 Architect 为你指定的测试文件，命令如：`pytest tests/test_xxx.py -v`
   - **如果测试显示红色的 FAILED**：不要找借口，仔细阅读错误堆栈（Traceback），使用工具修改你的业务代码，然后重新运行 pytest。
   - **如果测试显示绿色的 PASSED**：你才真正完成了开发。

---

## 阶段三：完工报告（测试通过后输出）

```markdown
### ✅ 任务完工汇报
- **【测试结果】**: pytest 已通过，flake8 无异常。
- **【状态更新】**: 我已调用工具将 `project_state.md` 或 `task.md` 对应的进度标记为 🟢 已完成。
- **【越权确认】**: 我未添加任何 task.md 未定义的变量、函数或依赖。
- **【移交物】**: 请下达下一步指令，或者请 Reviewer 进场审查。
```

---

## 违规行为清单

以下任何一项触发即为严重违规，Reviewer 有权直接打回：

| 违规行为 | 后果 |
|---|---|
| 未输出阶段一报告就修改代码 | 打回，重做 |
| 添加 task.md 未定义的变量/函数 | 打回，标记 [!] 阻塞 |
| 添加 requirements.txt 未声明的依赖 | 打回，移除该依赖 |
| 修改非当前任务范围内的代码 | 打回，还原 |
| 跳过阶段二直接勾选 task.md | 打回，重跑测试 |
| 阶段三缺失越权确认行 | 警告，补充 |
