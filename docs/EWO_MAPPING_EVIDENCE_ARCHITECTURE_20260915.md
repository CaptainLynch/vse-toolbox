# EWO 官方 HAR 与导出证据架构方案

日期：2026-09-15。状态：待用户确认，禁止据本提案直接实施。补充并细化 docs/DELIVERABLE_MAPPING_ARCHITECTURE_20260914.md。

## 证据与结论

用户附件 EWO.har 含347项请求。聚焦索引329、333、338及后续文件下载，未重放认证或调用内网。

- 官方使用 EWO_O/get，车型条件 _modelinfo like *F610S*，并设置责任部门条件。先page=1/pagesize=50，再page=1/pagesize=1000，maxRecords=2000。后一次返回410个EWO_O Item，均is_current=1、各有独立内部ID。
- 官方导出不是列表转CSV：调用 sgmw_mwt_downloadEworeportCall，ewoids传入410个内部ID，与上述列表ID集合完全一致；随后经File、下载token及vault下载XLSX。生成方法返回sgmw_outputFileRecord，属于可能产生服务器对象的操作，不应每次页面刷新自动调用。
- 附件XLSX实际为Innovator工作表、111列、410数据行。其dimension错误地声明只到第1行；重置范围后遍历实际XML行可读取全部数据。不能据openpyxl初始max_row=1判断报表为空。当前services/xlsx_preview.py直接遍历sheetData行，已有正确方向；后续需用合成异常dimension测试保护，不预断言当前解析器有同样缺陷。
- 列表与导出均有4条空EWO编号；非空业务编号406个且无重复。不能把407种含空值的列表编号计数解释为407个有效业务单号。
- 报表负责人及要求完成时间列各410行非空，阶段日期、停留天数和待签角色/人员属于额外导出字段；待签角色&人员列183行非空。非空统计不等于每一行字段已经与列表逐值一致。
- 列表状态：CLOSE233、PROC101、CANCEL27、IMPL25、DRAFT1 10、EDIT2 6、DRAFT2 3、OPEN3、EDIT1 2。阶段建模必须保留OPEN/CANCEL，不能自动归为CLOSE。

本次提供了查询与导出的现场成功证据，未证明多页边界、超过2000条、并发修改期间的一致性、重复导出幂等、所有工作表字段语义。方案不得将单次成功扩大为所有场景已验证。

## 当前实现与风险

services/project_status_connectors.py 的 ArasProjectStatusConnector 仅 crawl_ewo_report_all，再归档CSV/JSON；不会执行官方导出。当前数据来源能力却把备注语义描述为“当前阶段未签署的角色&人员”，该字段在本次列表响应里不存在。这是数据可用性与界面承诺不匹配，不能只调整UI文字后宣称字段已补齐。

现有共享聚合逻辑根据结果数量决定负责人/日期是否参与候选，当前身份归一化以业务编号为重要依据。应明确数据展示身份、业务关联键和授权写回身份，避免直接把历史全局去重逻辑替换后影响SOR/PAA/NCR。

## 推荐设计：列表为基础，官方导出为可选增强

保留现有列表采集、完整性检查和事务更新服务，在Aras集成层新增EWO官方导出适配器及来源专属规范化，不重写全系统。

基础快照来自列表，包含内部ID、EWO编号、车型、部门、负责人、要求日期、状态及版本。官方导出增强提供阶段时间、停留时长、待签角色/人员和111列表格分析。两个来源都保留抓取时间、参数签名、字段来源与版本，允许分别失败；基础查询成功不能掩盖增强失败。

UI显示“列表数据时间”“导出增强时间”“字段是否可用”，不能用空字符串同时代表未提供、尚未采集、来源空值和解析失败。

### 三种独立身份

- 记录身份：来源/报表/内部Item ID；版本使用modified_on、generation等明确字段，不能仅凭业务单号判断内容是否变化。
- 业务关联键：非空EWO编号，用于PAA/NCR关联与用户检索。空编号不参与自动业务关联，但保留原始记录及数量。
- 集合范围身份：规范筛选+来源连接身份范围+合同版本；成员集合及内容指纹分别存储，不能混作配置身份。

本次XLSX没有独立内部ID列。非空且两侧唯一的EWO编号可匹配增强字段，并做数量/状态等校验；4条空编号行不能按行号或导出顺序自动绑定到列表ID。保留为未关联增强行、明确统计。遇到未来重复编号同样拒绝自动拼接。若需要这类记录也可安全写回，应另取包含内部ID的官方合同，不能猜。

### 字段合同

| 项目字段/分析项 | 推荐来源 | 规则 |
| --- | --- | --- |
| 负责人 | 列表_rsp_name | 单记录模式才允许自动写入；不能当作当前审批人 |
| 计划完成日期 | 列表_required_date | 明确为要求完成时间；不与预计日期混用；确认日期/时区转换 |
| 当前阶段 | 列表state | 保留原值及规范值；OPEN/CANCEL明确显示，未知值不归完成 |
| 待签角色/人员 | 官方导出对应表头 | 仅安全关联且增强有效时可用；缺少字段不得清空现有备注 |
| 阶段日期与停留天数 | 官方导出命名字段 | 保留来源，日期与天数分别解释；不从提交日期猜阶段开始 |
| 业务编号/关联 | 列表_no及导出EWO编号 | 空编号只展示质量提示，不参与自动关联 |

### 单记录与集合模式

单记录模式绑定内部ID并展示业务编号；保留唯一性、版本、匹配范围与证据门禁。旧业务编号绑定不在迁移中直接改成内部ID，先唯一解析再确认/取证。

集合模式绑定查询范围，隐藏唯一外部键输入。负责人及计划日期默认手工，集合备注可以按批准模板生成。即使恰好只命中一条，也不隐式改变字段所有权。OPEN表示独立状态；CANCEL单独计数，是否属于已结束由业务政策确定，默认不算成功完成；空集合不算完成。

### 导出调用与文件边界

显式“刷新增强报表”或经用户启用的定时任务才调用生成方法；页面筛选复用快照，不重复生成。复用现有认证与安全下载设施，允许列表限制来源和跳转，下载token不落盘、不进审计文本；校验内容类型、ZIP结构及解析上限。

记录导出任务状态与输入ID集合摘要。生成后下载失败与生成前失败分开；不对可能已产生对象的方法盲目重试。现有证据不保证服务端幂等，实施时采用单任务互斥、明确失败阶段，并根据已获得文件引用恢复下载。

安全有界解析实际sheetData行，不信任dimension；表头按名称匹配并验证必需字段，允许额外列，不以列号固定身份。限制压缩/解压大小、行列数与处理时间。

## 快照、证据与更新

列表完整性门禁继续有效；410条小于1000是本次尾页证据，但不能跳过当前已有分页校验。导出ID集合记录于同一run，但官方导出发生在稍后，不能假定跨请求事务一致；列表版本与增强时间都展示。若发现列表变更、数量矛盾或非唯一关联，则阻止增强字段进入自动写回证据。

映射预览与执行使用同一来源字段注册及规范化函数。配置签名纳入绑定模式、来源类型、筛选、合同版本和增强要求。旧无增强证据不能授权写入待签字段。候选应记录字段可用状态，未提供字段采取不更新，只有明确且允许的源空值才考虑清空。

## 实施分期与验收

1. A：修正EWO语义与能力。模式明确、集合隐藏稳定键；未增强时禁用待签字段自动映射；显示基础与增强状态。保留旧接口兼容，新增规则不能悄悄改变已启用绑定。
2. B：实现官方导出适配、文件获取和111列解析，提供显式增强操作与快照。合成测试覆盖生成/下载失败、错误dimension、空ID选择、恶意跳转、解析上限和重复触发。
3. C：规范身份与安全关联。410条/406非空编号/4空编号的合成夹具，证明不按行序关联、不因空编号丢统计、重复编号不合并。新增字段候选与共享预览执行检查。
4. D：PAA/NCR只读关联及通用页面分阶段迁移，延续上一架构方案。该阶段不自动开放PAA/NCR字段写回。

各阶段先离线测试，再在目标环境由用户确认范围后复测；不会重放HAR里的登录或原始token。生产对照使用同车型、同部门、相近时间，比较列表数、非空编号数、导出行数和增强字段可用数。超期规则特别覆盖OPEN/CANCEL及缺日期，拒绝把未知/取消当正常完成。

## 评审结论

推荐批准A+B+C作为EWO首期，D作为后续项目。无需再采相同HAR即可开展首期实现；多页/大规模及导出错误恢复用合成边界测试，现场验收时再验证。空编号增强关联缺少可靠证据，首期明确不自动关联。
