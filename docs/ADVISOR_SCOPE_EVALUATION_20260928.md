## 二、明确不该咨询的场景

1. **需要现场/内网数据才能回答的**：TDC 503 的上游成因、Aras 网关/反代超时值、`sorPartList` 元素键名、某次录制里用户是否真的点过按钮。R3 §7 三项全部只能由现场取证或用户回答，顾问首轮只能把它们列为"缺失证据"。先取证，再定案。
2. **需要读仓库全量才能判断的**：跨 2400+ 用例的断言漂移影响面、某符号还有哪些消费方、`innerHTML` 盲区范围。这些 09-28 全部由本地聚焦检查解决（26 处 `.innerHTML` 逐处核对、12 条块作用域候选逐条复核、`_TDC_SOR_SOURCE_FIELDS` 消费点核对）。
3. **执行/环境类问题**：PyInstaller onefile 端口不释放、PowerShell 5.1 读无 BOM 中文脚本失败、微信 clawbot token 失效、broker 协议版本不匹配。有手册与可复现路径（`memory/RECOVERY_NOTES.md`），顾问不能跑命令。
4. **已定案且无新证据的重复确认**：同一决定同证据版本只 1 次。EXE-R2 一个任务已用 3 次 live（`668c4585` / `8d8db100` / `e66b6690`），第 4 次仍同版本就该停。
5. **顾问自身的治理元决策**：额度上限、试运行窗口、provider 路由、HOLD、参与范围。顾问读不到本机策略与账本，且它本身是被讨论对象。证据：09-25 13:16→09-27 15:57 那个 106.52M token 会话的用户消息时间线显示主体正是这类讨论（上限设 30、试运行换 Astra、参与范围评估），当时也确实没有为此咨询顾问——这个判断是对的，应保持。
