# 流程：用本地导出的表单生成签署日报（页面：每日进展；命令行：离线、只读）

> 适用版本：签署日报插件 `POST /import-form`、`POST /import-scan` 与 `tools/sign_daily_local_report.py`（2026-11-10 新增）
> 两种用法：页面里「用本地导出的报表生成」（含「扫描目录」自动挑最新），或命令行（`--file` / `--dir`）
> 口径来源：签署日报插件 `plugins/sign_daily/rules.py` 纯函数 + `service.compose`，与页面「生成」同源
> 设计依据：`.runtime/sign-daily-import-plan-20261110.md`（两轮 Astra-high 顾问评审后定稿的方案 B）
> **2026-11-16（插件 0.6.0）变更**：页面导入改为与此前的手工导入比「每日进展」（只写手工导入自有的
> 基线表，仍不碰一键生成的数据）；**命令行工具不变**，仍然零写库、不计算日变化。

## 1. 这个流程做什么、不做什么

**做**：拿一份你自己从 TDC 导出的「数模设计审核流程」表单（xlsx，官方 47 列），在本地算出当天的
「3D单签署进展日报」——摘要、三图数据、数据表、长周期初筛、待补录人员。

**不做**（与页面「生成」的差别，都是有意的）：

| 不做的事 | 原因 |
| --- | --- |
| 不写表单快照、不写一键生成的日报快照（`snapshot_*`）、不改配置 | 手工文件不进入共享快照表，避免污染交付物明细页/项目状态/统计/一键生成的日变化 |
| 不和一键生成的数据比日变化 | 两边的数据来源不同；页面导入只和**此前的手工导入**比（见下） |
| 不记住长周期复核结论 | 那要写 `long_cycle_conclusion`，本地模式一律不写 |
| 不自动发邮件 | 插件本来就只有 `.eml` 下载，没有 SMTP |

**页面导入的每日进展（2026-11-16 起）**：页面导入会把本次数据留作下次对比（只写手工导入自有的
`manual_baseline_meta` / `manual_baseline_rows` 两张表；取消勾选「留作下次对比」则只读不写）。
下次导入时自动和「最近一次更早的导入」比：汇总段带括号变化，并在来源声明后加「每日进展」一段
（一句话结论 + 只列有变化的单）。也可以在「更多：指定和哪一天比」里本次指定某一天，或把某一天
「固定」下来（固定的那天不受 90 天保留期清理）；优先级 **本次指定 > 固定 > 自动**。指定/固定的那天
不早于本次数据日期或不含所选项目时，**不显示日变化并说明原因，不会悄悄改用自动**。
基线的数据日期同样是用户确认的、未经系统核验；**两天的导出必须用同一套 TDC 筛选条件**，
否则少掉的单会显示为「消失」。命令行工具（步骤 3B）**不受影响**：仍然零写库、不计算日变化。

## 2. 前置条件

1. 本机有仓库的 Python 环境（`python` 可用，依赖已装好）。
2. 一份 **TDC 数模设计审核流程** 的官方导出 `.xlsx`，表头必须是 47 列契约（逐字一致）；
   工作簿里第一个工作表即可，名字不限；`.csv` 不支持。
3. （可选）**花名册** 与 **长周期规则** 的 CSV：在程序里进入「签署日报 → 设置」，用
   `roster` / `rules` 的「导出」得到（`姓名,科室` 与 `规则编号,零件名称,备注,别名,启用`）。
   不给就用内置种子——种子人数少，会显示大量「未在册」。

## 3. 五步流程

### 步骤 1｜导出表单

TDC → 数模设计审核流程列表 → 按需要的范围筛选 → 导出 Excel。**不要**手工删列、改表头、
排序后另存为别的格式；表头只要被改动一个字，工具会直接拒绝（这是设计意图）。

**xlsx 提示「受公司终端加密保护」时（2026-11-11 起支持）**：用 Excel 打开这份 xlsx →「文件 → 另存为」→
保存类型选 **Unicode 文本 (*.txt)** → 保存（Excel 提示「可能含有与文本不兼容的功能」选「是」）。
之后在下面的步骤里把 `.xlsx` 换成这份 `.txt` 即可，页面、扫描目录、命令行三处都认。注意：

- 只做「另存为」这一步，不要再用记事本等工具改这份 TXT（引号、列数一乱就会被拒绝）；
- 也接受「文本文件(制表符分隔)」，但那是 ANSI 编码，生僻字可能被 Excel 写成 `?`，优先用 Unicode 文本；
- 表头同样按 47 列逐字校验；这份 TXT 是磁盘上的明文副本，用完按公司要求自行处理。

### 步骤 2｜确认「数据截至日期」

自己确认这份文件代表哪一天的数据，格式 `YYYY-MM-DD`。三条禁止：

- 不要用**上传/运行时刻**当数据日期；
- 不要用**文件修改时间**；
- 不要用表里 `申请日期` 的最大值（那是逐行业务字段，不代表整表时点）。

工具不接受默认值，必须显式传 `--date`。

### 步骤 3A｜在页面里用（推荐）

签署日报页 → 左侧「用本地导出的报表生成（自动和上次导入比，看每日进展）」：

0. 数据截至日期已预填为今天（只是页面预填，看得见、可修改；后端从不用导入时间代替）；
   生成按钮上方有一句话说明这次会和哪一天比（如「将与 11-15 的导入（文件名）对比」
   「这是第一次导入，明天起才能看到每日进展」）。

1. **手动选文件**：选 `.xlsx` + 填「数据截至日期」→ 点「用这份报表生成」。选文件与扫描结果**互斥**（先选哪个用哪个），面板会显示「将使用：…」。
2. **扫描目录自动挑最新**：点「扫描目录」→ 程序扫监控目录，按**最后修改时间最晚**挑一份：
   - 选中后会显示文件名与修改时间；**数据日期仍要你自己填**（不会用文件时间代替）；
   - 最新那份表头不合格、或两份修改时间并列、或文件正在写入 → **不自动选中**，会显示原因，
     这时请修好文件或改用「手动选文件」，程序不会退回更旧的文件；
   - 目录只能是程序数据目录下的 `plugins/sign-daily/import/`（或部署方在环境变量
     `VSE_SIGN_DAILY_IMPORT_DIRS` 里授权的目录）；
   - 扫描结果只对本次会话有效（程序重启后重新扫描）。
3. 生成后，来源声明同时写进**正文首行**（复制出去也带着），页面顶部还有橙色徽标：
   `手工导入｜文件名｜数据截至日期（用户确认，未经系统核验）｜参与计算 N 行｜<日变化说明>`，日变化说明是下列之一：
   - `日变化基线（自动/指定/固定）：YYYY-MM-DD 的手工导入「文件名」，同为用户确认日期、未经系统核验`
   - `首次导入或无可用基线，不显示日变化`
   - `已有更晚日期的手工导入，本次按旧数据处理：不留基线、不显示日变化`
   - `指定的（或固定的）基线 YYYY-MM-DD 不早于本次数据日期或不含所选项目，未显示日变化`
   有基线时紧接着是「每日进展（较 MM-DD）」一段。「正文指纹」不含来源声明与日变化，同一份数据
   有没有对比、换哪种导入方式，指纹都相同。「下载 .eml 草稿」在此模式下被禁用（服务端也会拒绝）；
   收件人名单与偏好不保存。
4. 「图表配色」面板（左侧）可一键换方案或自定义颜色，右边的图马上重画；保存是可选的。

### 步骤 3B｜用命令行跑

最小用法：

```bash
python tools/sign_daily_local_report.py \
  --file "D:/导出/数模设计审核流程.xlsx" \
  --date 2026-11-06
```

不想每次点文件，就给一个目录（同一套挑选规则：只认最后修改时间最晚的，不合格不退回）：

```bash
python tools/sign_daily_local_report.py --dir "D:/导出/周报目录" --date 2026-11-06
# 会先在 stderr 打印「已选中（最后修改时间最晚）：xxx.xlsx」
# 若最新那份不合格 → 打印 E_HEADER_MISMATCH 并以 exit 1 结束，不会用旧文件顶替
```

带范围（项目/车型、科室可多次传或用逗号）：

```bash
python tools/sign_daily_local_report.py --file 表单.xlsx --date 2026-11-06 \
  --project F610M --department 车身科 --department 内饰科
```

带真实花名册/规则，并把 Markdown 报告写到文件：

```bash
python tools/sign_daily_local_report.py --file 表单.xlsx --date 2026-11-06 \
  --roster roster.csv --rules rules.csv \
  --md .runtime/日报-20261106.md
```

要机器可读全量（含三图明细、逐行 todo、长周期初筛结构）：

```bash
python tools/sign_daily_local_report.py --file 表单.xlsx --date 2026-11-06 --json
```

### 步骤 4｜核对输出（五节，逐节看）

1. **抬头**：`数据截至日期：…（用户确认，未经系统核验）｜文件：…｜参与计算：N 行`
   —— 行数应与导出行数对得上（已废弃单会被规则剔除，见 §5 异常提示）。
2. **摘要**：总签单/长周期两组指标 + 句子化的摘要行。
3. **三图数据**：图1 按区域（会签列）、图2 按科室、图3 审批人 + 待补录人员。
   图里数字为 0 或"（无）"时，先看是不是范围内本来就没有在途单。
4. **数据表**：流水单号 / 科室 / 阶段 / 会签·总（已签/应签）/ 停留天数 / 零件 / 待办。
5. **提示**：长周期初筛待确认、未在册人员、数据异常（状态未知、未签人数与字段不一致等）；
   若出现「状态列是数字码」的门禁提示，**不要对外发送**，先确认码值含义。

### 步骤 5｜使用

- 把 Markdown 里的内容贴进日报/飞书文档即可；**首行固定保留**
  `仅供核对｜手工导入｜不计算日变化` 与数据截至日期。
- 需要发邮件时：本流程**不生成** `.eml`（定稿口径：手工导入的报告不提供 .eml 出口），
  要发就用正文粘贴，并在开头写明数据截至日期与"用户确认"。

## 4. 参数表

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `--file` | 二者之一 | 官方导出 `.xlsx`（47 列契约） |
| `--dir` | 二者之一 | 监控目录：取最后修改时间最晚的 `.xlsx` 作为最新报表 |
| `--date` | 是 | 数据截至日期 `YYYY-MM-DD`，必须由人确认 |
| `--project` | 否 | 项目/车型，可多次或用逗号；缺省=表单里全部 |
| `--department` | 否 | 科室，可多次或用逗号；缺省=全部 |
| `--region` | 否 | 正文称呼里的区域，缺省 `车体区域` |
| `--roster` | 否 | 花名册 CSV（`姓名,科室`），缺省用内置种子 |
| `--rules` | 否 | 长周期规则 CSV，缺省用内置种子 |
| `--md` | 否 | 同时把 Markdown 写到该路径 |
| `--json` | 否 | 打印完整 JSON（含三图明细与逐行 todo） |
| `--max-rows` | 否 | Markdown 数据表最多打印行数，默认 30 |

## 5. 退出码与处置

| 退出码 | 含义 | 处置 |
| --- | --- | --- |
| `0` | 成功 | — |
| `1` | 表单不合格或范围内无单 | 看 stderr：`OfficialWorkbookContractError`（表头/列数不符，重新导出原样文件）、`OfficialWorkbookTruncated`（行数超上限）、`范围内没有 3D单`（换范围或确认文件是不是空的） |
| `2` | 参数/文件问题 | 文件不存在、日期格式不对、花名册/规则 CSV 路径不对 |

花名册 CSV 里出现「科室不在现行科室字典」会直接失败并指出行号——科室只能是
`车身科 / 车体科 / 内饰科 / 外饰科 / 车体架构集成科`（见 `rules.CURRENT_DEPARTMENTS`）。

## 7. 和页面「生成」的对齐关系

| 维度 | 页面「生成」（实时口径） | 本流程（本地表单） |
| --- | --- | --- |
| 数据来源 | 程序抓取后写入的表单快照 | 你给的 xlsx（或监控目录里 mtime 最新的那份） |
| 数据日期 | 快照时间换算 | `--date` 人工确认 |
| 日变化 | 与前一工作日基线比较 | 命令行：不计算、不读基线；页面导入：与此前的手工导入比（自有基线表） |
| 长周期复核记忆 | 可"确认并记住"（写结论表） | 只做只读初筛 |
| 落库 | 写零件级快照（日报基线） | 命令行：零写入；页面导入：只写手工导入自有的基线表 |
| 文件挑选 | 无（程序自己抓） | 人工选，或按 mtime 自动挑**候选**（不合格即停，不退回） |
| `.eml` | 可下载 | 不提供 |

口径本身（36 个必需列、会签/审批判定、长周期规则、指标公式）两端口径完全同源，
所以同一份数据两边算出来的指标应当逐字段相等——这也是后续把该流程做成页面入口时的验收断言。
