# 新用户可用性验收脚本（10 分钟独立上手）

## 一、验收目标与背景

### 1. 验收目标
验证 3 名从未接触过本工具的新用户（工程研发人员），在无系统管理员权限、无 Python 运行环境的标准办公电脑上，能否在 10 分钟（600 秒）内独立完成从获取压缩包到生成第一份有效签署日报的完整闭环。

### 2. 核心链路闭环
解压程序包 → 统一登录 → 新建项目（车型与默认科室） → 选择跟踪交付物 → 开机自启设置 → 完成向导并自动同步 → 生成第一份有效签署日报。

### 3. 验收通过基准
- 3 名测试用户必须全部在 600 秒内独立完成全流程。
- 全程不得触发任何系统管理员提权弹窗（UAC 拦截）。
- 全程不得需要任何外部环境配置（如安装 Python 或系统运行库）。
- 最终生成的签署日报必须完整展示图表与数据明细，无空白或报错。

## 二、测试环境与前置准备

### 1. 硬件与操作系统环境
- 操作系统：标准 Windows 10 / Windows 11 办公电脑。
- 账号权限：标准受限域用户权限（普通员工账号），**严禁授予管理员权限**。
- 运行环境：未安装 Python，未配置任何开发工具环境变量。
- 网络环境：正常接入办公内网，具备访问统一身份认证系统与相关业务系统的网络权限。

### 2. 现场物料与预置准备
1. **安装程序包**：已将打包好的程序压缩包放置在测试电脑的“桌面”。
2. **测试提示卡（纸质或桌面便签）**：
   - 统一登录测试账号：`test_user_01`（或对应的用户编号账号）
   - 统一登录测试密码：`Pass****2026`
   - 目标车型代码：`MODEL-A`
   - 跟踪交付物范围：保持系统默认推荐项
   - 日报生成条件：默认项目与当天日期
3. **计时工具**：观察员配备高精度秒表（或专用计时软件），精确到秒。
4. **纸质记录表**：打印好的《新用户可用性验收记录表》。

### 3. 计时起点（T0）定义
- 观察员确认测试用户就座并阅读完测试须知。
- 观察员发出“测试现在开始”口令，用户**首次触碰鼠标或敲击键盘**的瞬间，秒表立即启动，记为 **T0 = 0 秒**。

## 三、观察员指令与话术规范

验收的核心原则是**“只观察、不干预、不暗示、不代劳”**。观察员必须严格克制协助冲动，真实记录用户的认知卡点。

### 1. 观察员行为红线
- **绝对禁止代操作**：严禁碰触测试电脑的鼠标、键盘或屏幕。
- **绝对禁止位置指引**：严禁说出“点右上角”、“看中间那个绿色按钮”等方位指引。
- **绝对禁止预警纠错**：当用户选错选项或在寻找入口时，不得发声提醒或叹气。
- **保持客观距离**：站立或就座于用户侧后方约 1 米处，保证能看清屏幕与记录用时，但不得对用户造成压迫感。

### 2. 观察员标准回复话术
当用户遇到疑惑并向观察员提问时，观察员仅允许使用以下标准话术进行应答：

| 用户提问场景 | 观察员标准应答话术 | 备注说明 |
|---|---|---|
| “这个压缩包解压到哪里？” | “请按照您平时的办公习惯，解压到您常用的文件夹即可。” | 引导用户自主选择桌面或常用工作文件夹 |
| “登录账号和密码填什么？” | “请参考桌面测试提示卡上的账号和密码信息。” | 指引看材料，不念出具体字符 |
| “这个项目名称和车型怎么选？” | “请根据测试提示卡上的要求，结合界面说明进行选择。” | 让用户阅读界面下拉框和选项 |
| “接下来我应该点哪个按钮？” | “请根据屏幕上的提示信息，按您的理解继续操作。” | 坚决不给步骤指引 |
| “这里在转圈，是卡住了吗？” | “系统正在处理中，请稍加留意屏幕上的状态提示。” | 缓解焦虑，观察界面是否有清晰状态反馈 |
| “开机自启这个我需要勾选吗？” | “您可以根据界面提示和您个人的日常偏好决定是否开启。” | 观察向导默认选项对用户的引导效果 |
| “日报应该去哪里生成？” | “请查看系统界面中的导航和功能入口，按您的直觉操作。” | 考验导航重组后「报告」入口的易寻性 |
| “我这样操作是对的吗？” | “您按照平时的使用习惯继续操作即可，我们只记录流程。” | 消除被考核的心理负担 |
| “还有多长时间？我超时了吗？” | “请放平心态，按照您的正常节奏操作即可。” | 不播报剩余时间，避免制造紧张 |

## 四、分步验收流程与详细计时点

全流程分为 8 个连续步骤，总目标用时 480 秒，总上限用时 600 秒（10 分钟）。各步骤目标用时之和（480 秒）严格低于总上限（600 秒），并留出合理的操作冗余与思考缓冲。

```
[T0: 0s] 
   ↓ 步骤1: 解压与启动 (目标60s / 累计60s / 上限90s)
   ↓ 步骤2: 欢迎界面 (目标20s / 累计80s / 上限120s)
   ↓ 步骤3: 统一登录 (目标60s / 累计140s / 上限200s)
   ↓ 步骤4: 新建项目 (目标50s / 累计190s / 上限280s)
   ↓ 步骤5: 选择交付物 (目标40s / 累计230s / 上限340s)
   ↓ 步骤6: 开机自启设置 (目标20s / 累计250s / 上限370s)
   ↓ 步骤7: 完成向导并自动同步 (目标90s / 累计340s / 上限480s)
   ↓ 步骤8: 生成首份有效签署日报 (目标140s / 累计480s / 上限600s)
[完成: 目标480s (总上限600s)]
```

### 步骤 1：解压程序包与启动程序
- **步骤目标**：新用户在桌面找到压缩包，完成解压，并在解压文件夹中找到主程序双击启动。
- **计时区间**：从 T0 开始，到主程序界面窗口完整渲染呈现为止。
- **目标用时**：60 秒 | **累计目标**：60 秒 | **步骤累计预警上限**：90 秒
- **用户预期操作**：
  1. 选中桌面的压缩文件，右键选择解压到当前文件夹或指定文件夹；
  2. 打开解压生成的程序文件夹；
  3. 识别出主程序图标，双击运行；
  4. 观察到主程序窗口正常弹出，未弹出黑色的底层控制台窗口。
- **观察员记录要点**：
  - 用户是否容易在解压后的文件夹中认出主程序；
  - 是否出现因解压未完成便尝试运行导致的异常；
  - 启动后是否无任何提权弹窗、无报错对话框。

### 步骤 2：向导第 1 步·欢迎界面
- **步骤目标**：进入首次使用向导，了解产品简要功能，开启新手配置。
- **计时区间**：从程序主窗口出现，到点击“开始配置”或“下一步”按钮进入登录页为止。
- **目标用时**：20 秒 | **累计目标**：80 秒 | **步骤累计预警上限**：120 秒
- **用户预期操作**：
  1. 浏览欢迎界面的核心介绍与流程指引；
  2. 点击界面主按钮（如“开始使用”或“下一步”）。
- **观察员记录要点**：
  - 界面文案是否清晰易懂，有无令用户疑惑的表述；
  - 主操作按钮是否醒目，用户是否能瞬间定位。

### 步骤 3：向导第 2 步·统一登录
- **步骤目标**：完成一次登录，连通相关业务系统，并启用安全密码保存。
- **计时区间**：从进入登录页，到登录成功进入新建项目向导页为止。
- **目标用时**：60 秒 | **累计目标**：140 秒 | **步骤累计预警上限**：200 秒
- **用户预期操作**：
  1. 查看统一登录表单；
  2. 输入测试提示卡上的域账号与密码；
  3. 确认勾选“记住登录凭据以便自动同步”；
  4. 点击“登录并连通”按钮；
  5. 界面显示连接验证成功，自动或点击进入下一步。
- **观察员记录要点**：
  - 登录过程是否有明确的原位加载反馈；
  - 连通状态是否清晰提示“已连接”；
  - 密码保存说明是否让用户感到安心（仅存本机、受个人账户保护）。

### 步骤 4：向导第 3 步·新建项目（车型与默认科室）
- **步骤目标**：创建首个工作项目，设定车型代码与负责科室。
- **计时区间**：从进入项目设置页，到完成输入并点击下一步为止。
- **目标用时**：50 秒 | **累计目标**：190 秒 | **步骤累计预警上限**：280 秒
- **用户预期操作**：
  1. 在车型选择框中检索或下拉选中指定车型代码（如 `MODEL-A`）；
  2. 查看默认勾选的业务科室（车体科、车身科、内饰科、外饰科、车体架构集成科）；
  3. 确认科室配置无需修改，点击“下一步”。
- **观察员记录要点**：
  - 车型下拉搜索框是否顺畅，用户能否在 15 秒内找到目标车型；
  - 默认科室是否满足预期，用户是否产生多余的修改犹豫。

### 步骤 5：向导第 4 步·选择要跟踪的交付物
- **步骤目标**：选定该项目需要重点跟踪的核心交付物。
- **计时区间**：从进入交付物选择页，到点击下一步为止。
- **目标用时**：40 秒 | **累计目标**：230 秒 | **步骤累计预警上限**：340 秒
- **用户预期操作**：
  1. 查看系统推荐的默认交付物列表；
  2. 核对重点交付物（如 3D 数模交付物、工程变更单、问题跟踪清单等）的勾选状态；
  3. 保持推荐配置，点击“下一步”。
- **观察员记录要点**：
  - 交付物名称是否通俗专业，用户能否看懂列表含义；
  - 用户是否能快速确认默认项并推进。

### 步骤 6：向导第 5 步·开机自启询问
- **步骤目标**：完成开机自启动选项的确认（默认关闭）。
- **计时区间**：从进入开机自启设置页，到点击下一步为止。
- **目标用时**：20 秒 | **累计目标**：250 秒 | **步骤累计预警上限**：370 秒
- **用户预期操作**：
  1. 阅读开机自启的功能说明（后台静默同步数据、不影响开机速度）；
  2. 观察默认选项处于关闭状态；
  3. 不作修改，保持默认关闭，点击“下一步”。
- **观察员记录要点**：
  - 默认关闭策略是否明确表达，未对用户产生误导；
  - 说明文案是否解答了用户的顾虑。

### 步骤 7：向导第 6 步·完成向导并开启第一次同步
- **步骤目标**：向导完成，系统自动触发首次数据同步，并在界面上呈现清晰的同步进度与成功提示。
- **计时区间**：从点击“完成并开始同步”，到首轮同步完成并进入主工作台界面为止。
- **目标用时**：90 秒 | **累计目标**：340 秒 | **步骤累计预警上限**：480 秒
- **用户预期操作**：
  1. 点击“完成并开始第一次同步”按钮；
  2. 观察界面原位展示的同步进度条与状态文字；
  3. 等待数据抓取与校验完成，看到“同步成功”状态；
  4. 界面自动转入主工作台或提示进入主界面。
- **观察员记录要点**：
  - 同步期间是否有平滑的进度展示或加载动画；
  - 是否有清晰的“数据同步已完成”成功反馈；
  - 数据同步阶段是否稳定，无静默卡死。

### 步骤 8：生成第一份有效签署日报
- **步骤目标**：在主界面找到报告入口，进入签署日报，设置并生成包含有效数据的完整日报。
- **计时区间**：从进入主工作台，到成功生成并完整预览签署日报为止。
- **目标用时**：140 秒 | **累计目标**：480 秒 | **步骤累计上限**：600 秒
- **用户预期操作**：
  1. 在顶部或侧边导航栏点击“报告”；
  2. 在报告中心卡片中选择“3D单签署日报”；
  3. 确认当前项目与报表生成选项；
  4. 点击“生成日报”按钮；
  5. 系统完成数据整理并呈现预览视图；
  6. 用户在右侧预览区查验“三图一表”（总体进度图、科室完成率图、状态分布图、单据明细表）完整显示；
  7. 查验可复制正文或导出邮件选项可用。
- **观察员记录要点**：
  - 用户能否迅速在主导航找到“报告”入口；
  - “生成日报”按钮是否突出；
  - 日报生成时间是否合理（通常在 10~25 秒内完成响应）；
  - 查验最终生成的图表数据是否完整真实，无占位错乱。

## 五、失败中止判据

测试过程中若出现下列任一情形，观察员应立即宣布测试中止，并在记录表中勾选“未完成”并记录详细原因：

1. **总时间超限中止**：
   - 无论处于哪一步骤，只要自 T0 起累计耗时达到 **600 秒（10 分钟整）**，秒表鸣响，观察员立即宣布“时间到，测试中止”。
2. **管理员权限阻断中止**：
   - 运行、配置或同步过程中，系统弹出 Windows 用户账户控制（UAC）弹窗要求输入管理员凭据，且普通员工无法绕过，立即中止。
3. **运行环境缺失中止**：
   - 程序因依赖缺失（如弹出缺少 Python 环境、缺少 DLL 动态链接库或运行时报错）导致无法正常运行，立即中止。
4. **致命异常与程序死锁**：
   - 软件发生白屏、界面崩溃闪退，或处于无响应卡死状态超过 60 秒且无任何恢复迹象，立即中止。
5. **外部协助违规中止**：
   - 观察员因口误提示了关键操作位置，或有其他同事介入提供操作协助，导致独立性原则被打破，本次样本作废并中止。
6. **用户主动放弃**：
   - 用户因界面逻辑混乱产生严重挫败感，明确表达“无法理解、放弃测试”，立即中止。

## 六、每人通过标准与整体验收判定

### 1. 单人通过标准（必须同时满足以下 4 项）
- **独立性达标**：全过程 100% 由用户独立理解界面并完成操作，未获得任何外部干预。
- **环境达标**：全程无管理员权限弹窗，无任何额外环境安装操作。
- **时效达标**：从 T0 至步骤 8 完成，实际总用时严格小于或等于 600 秒（≤ 10 分钟）。
- **产物达标**：成功生成并完整预览第一份签署日报，报表的三图一表结构完整，数据有效，无渲染错误。

### 2. 整体验收结论判定
- **验收通过（合格）**：**3 名新用户全部达到单人通过标准**（3/3 成功率 100%，且全部在 10 分钟内完成）。
- **验收未通过（不合格）**：只要有 **1 名及以上**用户超时、中止或未能生成有效日报，整体验收即判定为“不通过”。
- **整改与复测**：若验收不通过，研发与交互团队必须根据《验收记录表》中的卡点明细，在 3 个工作日内完成针对性优化，并重新抽取 3 名从未用过的新用户进行二次验收。

## 七、测试后环境复原指南

为确保 3 名用户的测试环境完全隔离、互不影响，每位用户测试结束后，观察员须在 3 分钟内完成环境清理：

1. 关闭正在运行的本软件及所有浏览器窗口；
2. 清理桌面生成的解压文件夹及临时产物；
3. 清理用户个人应用数据目录下的工具配置文件与数据库文件；
4. 确认系统启动项未残留开机自启条目；
5. 重新将原始的发布压缩包复制至桌面，准备下一位用户的测试。
