# EWO v2 实施与验收说明（2026-09-15）

## 已实现

- 旧版绑定继续按原规则执行，不自动迁移，不改变原字段归属。
- 新版显式区分固定单条记录与记录集合。单条绑定内部记录 ID，版本失效不跟随同号新记录；集合始终禁止负责人、计划日期自动映射。
- v2 进入配置签名。迁移须先停用保存，再完成两次新合同取证后启用；旧页面不能修改 v2，数据库事务比较修订号，防止迁移期间旧请求覆盖配置。
- 数据库版本升级到 14，以便旧 EXE 在写入前拒绝打开新版库。升级保留旧规则与字段归属。
- 官方导出是独立只读增强快照。准备只查询完整集合，用户显式生成；生成结果未知禁止重发，已保存文件引用可恢复下载。任务及恢复按登录主体、固定来源和筛选签名隔离。
- 关联仅采用两侧唯一的非空业务编号；空号、歧义、未关联均保留。内部 ID 分析保留同号/空号的不同记录。空备注不会作为清空项目备注的依据。
- 增强页面分别显示基础/增强时间、关联计数、基础记录 ID，支持显式恢复。固定单条增强仅导出选定的内部 ID。

## 使用与升级

1. 关闭旧程序，备份完整 `data` 目录及旧 EXE。新程序会将数据库升级为 v14；旧 EXE 不再打开升级后的库。回退须同时恢复升级前数据库和旧程序。
2. 将新包解压到新目录，需要沿用数据时复制已有 `data` 的副本；不要覆盖原始备份。
3. 在系统设置重新登录域账号。已有旧会话不含主体绑定，不能直接恢复增强任务。
4. EWO详情的旧版合同可继续保留。迁移时选择新版集合或固定单条，先取消启用并保存。集合负责人/计划日期变为手工；固定单条填写内部记录ID及筛选条件。再次取得两次一致证据，检查映射后启用。
5. 在增强区域点击“准备增强导表”。该动作不会生成源系统报表；展开基础记录ID可查阅原始内部ID。随后点击“生成并读取增强”才调用官方生成方法。
6. 生成结果未知时到源系统核对，禁止重复生成。下载/解析失败可继续读取已生成报表。重启后可按相同账号与筛选条件“恢复上次任务”。

增强字段不会自动更新项目负责人/日期，也不反写源系统。PAA/NCR未扩展为新的增强导表链路。使用Excel功能时继续保留同目录的既有 `VSE-ExcelWorker.exe`；本修复包只更新WebUI与CLI。

## 分工与证据

关联纯函数、工作簿适配、独立面板、v2校验分别由4次ZCode Gemini Flash隔离任务产出。主控检查实际结果并修复状态大小写、错误断言、无效任务ID和控件/后端集成问题。另一次Gemini审查仅检查提供的源码摘录，未发现该范围P1/P2问题；不等于全库独立审计。

主控负责身份、签名、并发、迁移、下载边界、集成与最终验证。执行记录保存在本地 `.runtime/ewo-v2/`，未向worker提供原始HAR、报表数据或凭据。

## 验收边界

合成测试、附件离线解析及本机打包启动能验证代码合同；本轮未使用内网账号执行真实生成/下载。现场仍需验证账号权限、网络、源系统当前响应以及一条固定记录和一个小集合的实际结果。源报表410行、111列的离线证据与406唯一编号+4空编号关联结果已核验。
